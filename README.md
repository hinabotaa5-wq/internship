# Wi-Fi 診断アプリ

インターンで開発した、家庭向け Wi-Fi トラブルの切り分けを支援する Web アプリケーションです。

このリポジトリは**ソースコードと説明用**です。公開デモはありません。

## 何をするアプリか

「繋がらない・遅い・切れる」といった症状から、利用者が自分で原因の見当をつけられるようにします。質問に答えて診断し、部屋の間取りとルーター位置を置いて電波のイメージを確認したうえで、必要なら問い合わせ番号を発行してサポートにつなげます。

想定している流れは次のとおりです。

1. 症状に近い選択肢を選ぶ（原因切り分け診断）
2. 部屋の形とルーター位置を画面上で置く（住宅レイアウト）
3. 電波の強弱をヒートマップで見る
4. 診断結果と間取りを添えて問い合わせチケットを発行する

## 主な機能

- **原因切り分け診断**  
  症状ごとの質問ツリー。回答に応じて次の質問が変わり、回線・機器・端末・電波など、次に疑うポイントを返す。質問データと分岐は Flask に依存しないモジュールに分離している。
- **住宅レイアウト作成**  
  部屋の形状とルーター位置を配置する。レイアウトは JSON として持ち、後段のヒートマップとチケットに渡す。
- **ヒートマップ**  
  間取りとルーター位置から電波強度のイメージと改善のヒントを出す。計算はフロントエンド側の関数に寄せ、サーバーは画面遷移とセッション読み出しを担当する。
- **問い合わせ受付**  
  間取り・Q&A 履歴・診断結果をチケットに保存し、受付番号で利用者とスタッフ画面を紐づける。
- **ユーザー認証**  
  ログインによる利用者管理（Flask-Login）。

## 技術スタック

- Python 3.12 / Flask 3 / Bootstrap 5
- MySQL（Flask-SQLAlchemy / Flask-Migrate）
- パッケージ管理: uv
- 開発: VS Code Dev Container（Docker Compose）
- インターン期間中の実行環境: Docker イメージを AWS（ECR / ECS）へ載せる構成

## 構成

```
.
├── src/web/
│   ├── auth/        # 認証
│   ├── diagnosis/   # 原因切り分け診断
│   ├── floorplan/   # 間取り・ルーター配置
│   ├── heatmap/     # ヒートマップ画面
│   ├── wifi/        # トップなど診断アプリの画面
│   ├── tickets.py   # 問い合わせ API
│   ├── app.py       # アプリケーションファクトリ
│   └── models.py    # DB モデル
├── migrations/      # DB マイグレーション
├── docker-images/   # 実行用 Docker
└── .devcontainer/   # 開発用コンテナ
```

画面は Blueprint ごとに分け、診断ロジック（`diagnosis/engine.py`）と画面のルーティングを分離しています。

## データ

問い合わせは `Ticket` モデルで持ちます。

- `ticket_number`: 受付番号
- `room_layout`: 間取り（JSON）
- `qa_history`: 診断の回答履歴（JSON）
- `diagnosis_result`: 診断結果（JSON、診断せずに問い合わせる場合は空でもよい）
- `created_at`: 作成日時
